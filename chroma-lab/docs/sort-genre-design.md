# 分类玩法设计稿：从「倒水」到一整个品类

> 面向 Chroma Lab（本仓库）的后续版本与衍生产品。
> 目的不是罗列点子，而是先把「倒水分类」这个玩法**拆成可调的旋钮**，
> 再用这些旋钮推导出一批彼此**机制不同**（而非换皮）的变体，并给出优先级判断。

## 1. 机制拆解：它为什么好玩

### 1.1 它其实是「藏起来的三消」

一个容器装 4 层，4 个同色元素合到一起就「封瓶」消失。凑齐 4 个通常需要 3 次移动。
和三消的区别只有一处，但很关键：**三消的消除条件是空间相邻，倒水的消除条件是「访问顺序」**。

因为液体只能从瓶口进出，每个容器都是一个**栈（LIFO）**。玩家真正在解的问题是：
> 一堆栈之间只能做「弹出顶部同色连续段 → 压入另一个栈」的操作，如何把它们整理成单色栈。

这一个约束带来了全部难度：**你想要的东西常常被自己需要的东西压着**。

### 1.2 三个稀缺资源

| 资源 | 为什么稀缺 | 玩家的策略语言 |
|------|-----------|--------------|
| 空容器 | 唯一能无条件接收的目标 | 「别浪费空瓶」 |
| 顶层可见性 | 只有顶层能动 | 「先挖开哪一瓶」 |
| 剩余空间 | 目标瓶装不下就只能倒一部分 | 「先倒零头还是先倒整段」 |

难度旋钮的本质就是**改变这三种资源的供给**：少给一个空瓶远比多给一种颜色更难，这一点在本作的关卡曲线里也成立（每 5 关一次「仅 1 空瓶」）。

### 1.3 情绪曲线：为什么它适合碎片时间

- 无时间压力 → 可随时中断
- 每次「封瓶」都是一次即时正反馈（视觉 + 触感 + 音效三重）
- 失败不惩罚：撤销、重玩、加瓶都能兜住，卡关不流失
- 单局 30 秒到 3 分钟

**设计红线**：任何变体都不能破坏这四条。加入「限时」「体力扣关」「不可逆失败」时必须极其小心——那是另一条用户曲线。

## 2. 泛式：八个旋钮

任何一个「分类整理」小游戏都可以写成下面这张表的一组取值。这是本文档最该被复用的部分。

| # | 旋钮 | 取值举例 | 影响 |
|---|------|---------|------|
| 1 | **容器 Container** | 栈（瓶）/ 双端队列（书架）/ 队列（传送带）/ 槽位集合（托盘） | 决定「什么被压住了」 |
| 2 | **容量 Capacity** | 统一 4 / 异构（本作的 6·10·14·18 大瓶）/ 无限 | 异构容量能凭空造出一个必经目标 |
| 3 | **元素 Element** | 颜色 / 数值 / 形状 / 音符 / 图标 | 决定「相同」的定义 |
| 4 | **合并规则 Merge** | 同色相邻可叠 / 精确凑和 / 按序列匹配 / 反应生成新元素 | 决定解题的运算类型 |
| 5 | **可达性 Access** | 全连通（任意瓶可倒任意瓶）/ 图受限（相邻股道）/ 单向阀 | 从「全排列」变成「路径规划」 |
| 6 | **信息 Information** | 完全可见 / 未知层 / 遮蔽容器 / 目标未知 | 决定是「规划」还是「试探」 |
| 7 | **目标 Goal** | 每容器单色 / 匹配配方 / 拼出图案 / 清空全场 | 决定关卡的可读性 |
| 8 | **压力 Pressure** | 无 / 步数评级 / 元素衰减 / 位置推进 | 决定情绪曲线 |

用这张表回看已知产品：

| 产品 | 容器 | 容量 | 元素 | 信息 | 备注 |
|------|------|------|------|------|------|
| 经典 Water Sort | 栈 | 统一 4 | 颜色 | 全可见 | 基线 |
| Magic Sort! | 栈 | 统一 4 + 活动关超长试管 | 颜色 | 未知层 + 遮蔽瓶 | 只动了旋钮 2 和 6 |
| Ball Sort | 栈 | 统一 4 | 彩球 | 未知层 | 只换了表现层 |
| 螺丝排序 | 槽位 | 按孔位 | 螺丝 | 部分遮挡 | 动了旋钮 1 |
| Tile Match 融合 | 槽位 | **不再统一** | 图标 | 全可见 | 动了旋钮 2、4 → 退回三消 |
| **Chroma Lab（本作）** | 栈 | **异构：4 + 6/10/14/18** | 颜色 | 未知层 | 见 §3 |

**一眼可见的空白**：旋钮 4（合并规则）、5（可达性）、7（目标）几乎没人动过。下面的变体优先往这三个方向走。

## 3. 本作已经落地的差异点

Chroma Lab 不是「再做一个水排序」，它动的是旋钮 2 与 7：

- 中央大瓶容量恒为 **4n+2**，且有一种专属色的总量**恰好等于大瓶容量**
- 于是这种颜色在 4 层的普通瓶里**永远凑不满一瓶**，唯一解法是全部灌进大瓶
- 结果：每关都有一条**必经主线**（把专属色一段段汇聚进大瓶）+ 若干支线（其余颜色各自归位）

这条约束的价值在于：它**不需要任何新的规则说明**。玩家试两次就发现「这颜色装不满普通瓶」，自己推出结论。这是同类产品里罕见的、靠数学约束而非 UI 提示传达的设计。

配套引入的两条成熟机制（来自 §0 的资料）：

| 机制 | 本作实现 | 与原产品的差异 |
|------|---------|--------------|
| 未知色层 | 第 7 关起出现，每 3 关 +1 层，上限 6；只藏液面之下，浮出即揭晓；同瓶最多 2 层 | 原作用于拉长关卡；本作额外约束「同瓶最多 2 层」，避免信息过度集中变成纯猜 |
| 死局加瓶 | 每关免费 1 次 | 原作是 900 金币付费点；本作无经济系统，改为免费但限次，保留「资源有限」的决策感 |

## 4. 原创变体设计稿

每个变体都标注它**动了哪个旋钮**——这是判断「是否只是换皮」的唯一标准。

### 4.1 分层特调（旋钮 4·7：合并规则 → 序列匹配）

- **一句话**：不是把同色收在一起，而是照着配方单把液体**按顺序**叠出来。
- 容器：调酒杯（栈，容量 4~6），每关给 2~4 张配方单（如 `底→顶：奶白·焦糖·浓缩·奶泡`）
- 核心变化：目标从「单色」变成**指定序列**。因为栈是 LIFO，配方必须**倒序构造**——玩家要先想清楚最后一层是什么。
- 胜利：所有配方杯与配方单完全一致，其余容器空
- 难度旋钮：配方长度、配方之间共用同一种原料的比例、是否允许「多余原料倒进水槽」（水槽 = 一次性垃圾桶，用完即封）
- 独特钩子：**倒序思维**。同一批素材，配方顺序不同就是完全不同的题目，关卡产能极高
- 风险：可读性下降，需要在杯身旁边持续显示配方缩略图

### 4.2 精确配液（旋钮 3·4：元素 → 数值）

- **一句话**：每层液体带一个刻度数字，容器必须**凑出精确总量**，多一滴都算废。
- 容器：量瓶，瓶身写着目标值（如 `100 mL`）；元素：`10 / 20 / 25 / 50` 的液滴段
- 核心变化：合并条件从「同色」变成「和等于目标」。同色仍可叠，但叠错就凑不出目标
- 胜利：每个量瓶恰好达标并封口
- 难度旋钮：目标值的因数分解方案数（唯一解最难）、是否允许倾倒一部分（部分倒出会把整数拆开）
- 独特钩子：**心算 + 背包问题**的轻量版，适合做「教育向」与「成人休闲」双 SKU
- 风险：数值会劝退纯休闲用户，需要把数字做成一眼可数的刻度而非裸数字

### 4.3 书架归位（旋钮 1：容器 → 双端队列）

- **一句话**：书从**书架两头**都能抽能插，但中间的书动不了。
- 容器：书架层（双端队列，容量 5~8）；元素：书脊（按索书号排序，不是分组）
- 核心变化：栈变 deque，可达性翻倍，难度不降反升——因为目标从「分组」变成**全序排列**
- 胜利：每层书按索书号升序排好
- 难度旋钮：书架层数、乱序度（逆序对数量）、是否有「不能移动的固定书」
- 独特钩子：deque + 排序目标是一个**全新的解空间**，与三消毫无关系；主题天然适合女性向与「治愈整理」赛道
- 风险：求解器难度上升（排序目标的状态空间更大），需要限制层数

### 4.4 调度场（旋钮 5：可达性 → 图）

- **一句话**：车厢只能推进相邻股道，不能凭空飞过去。
- 容器：股道（栈或 deque），股道之间有**固定连接图**（不是全连通）
- 核心变化：每一步不再是「任意 A→B」，而是「A→与 A 相连的 B」。玩家要同时解决**分类**与**路径**
- 胜利：每条股道编组成同型车厢
- 难度旋钮：连接图的稀疏度、是否有单向道岔（旋钮 5 的极端值）、中转股道数量
- 独特钩子：连接图本身就是关卡内容——**同一套车厢，换一张图就是新关卡**，关卡生成成本极低
- 风险：需要把连接关系画清楚，否则玩家会误判可倒目标；建议连线常显 + 选中时高亮可达目标

### 4.5 显影（旋钮 6·7：信息 → 目标未知）

- **一句话**：不告诉你要分成什么样，只给你一张**逐渐显影的底片**。
- 容器：显影槽（栈，容量 4）；元素：色块
- 核心变化：目标图案初始是模糊的，每完成一个容器就显影一块，玩家在「不完全知道目标」的情况下推进
- 胜利：拼出完整底片（每个容器对应图案的一列）
- 难度旋钮：显影速度、误差容忍（是否允许某列错一格）
- 独特钩子：把「未知」从**手牌**移到**目标**上，这是资料里所有产品都没做过的方向；收尾时的图案揭晓是天然的分享点
- 风险：目标未知会削弱规划感，必须保证「任何时刻都存在不后悔的走法」，否则玩家会觉得被骗

### 4.6 反应釜（旋钮 4：合并 → 生成新元素）

- **一句话**：两种试剂相遇会变成第三种，不可逆。
- 容器：反应釜（栈，容量 4）；元素：试剂色 + 一张公开的反应表（`蓝+黄=绿`）
- 核心变化：倒液不再是搬运，而是**转化**。有些颜色场上根本没有，必须自己合成
- 胜利：每釜装满目标产物
- 难度旋钮：反应表的深度（是否需要二级合成）、是否存在「废液」（错误组合生成无用物，只能占位）
- 独特钩子：从「整理」升级为「合成」，玩家目标从消除变成**制造**，成就感完全不同
- 风险：不可逆 + 可生成废液 = 容易出现必败局面。**必须**由求解器在生成时保证可解，并把「加瓶」换成「排废」道具

### 4.7 传送带（旋钮 8：压力 → 位置推进）

- **一句话**：每 5 步整排容器右移一格，最右侧那个**直接出厂**。
- 容器：传送带上的箱子（栈）；元素：货物
- 核心变化：引入**空间时限**——你不是没时间，而是「这个容器还剩 3 步就要走了」
- 胜利：在容器离场前把它装成单色；离场时未完成则计入损耗，损耗超额判负
- 难度旋钮：推进步长、传送带长度、是否有「拉回」道具
- 独特钩子：给这个无压力品类加入**可预测的**紧迫感（不是倒计时，而是步数刻度，玩家能算），保留策略性
- 风险：这条明确违反 §1.3 的红线之一，**只适合做活动模式或独立 SKU**，不要塞进主线关卡

### 4.8 听色（旋钮 3 + 无障碍：元素 → 音高）

- **一句话**：每种液体有自己的音高，倒液就是弹音；连续同色段越长，和声越完整。
- 容器：音轨管（栈）；元素：音符色块
- 核心变化：**听觉成为第二条信息通道**——色觉障碍玩家可以靠音高识别颜色
- 胜利：每根管子成为单一音色，收尾时自动播放一段完整旋律
- 难度旋钮：音阶数量（= 颜色数）、是否隐藏部分颜色只给音高（旋钮 6 与 3 的组合：**只能听不能看**）
- 独特钩子：把无障碍设计变成玩法本身，而不是补丁。「只能听不能看」的关卡是真正独一无二的挑战模式
- 风险：依赖音频，静音场景下必须可降级为纯视觉

### 4.9 归档室（旋钮 2·7：容量异构 → 空间规划）

- **一句话**：容器容量从 2 到 9 不等，元素总量正好填满全场，一格都不能浪费。
- 容器：档案格（栈，容量各异）；元素：文件色标
- 核心变化：本作「大瓶 4n+2」思路的完全泛化——**每种颜色的总量都是一个独特的数**，必须匹配到容量正好相等的容器
- 胜利：每个容器按自身容量装满单色
- 难度旋钮：容量的分布（质数容量最难）、是否给缓冲格
- 独特钩子：这是一个**装箱问题**，谜题气质从「整理」偏向「数独」，适合做硬核向的日更挑战
- 风险：需要在容器上清晰标注容量（本作已用刻度线 + 数字标签验证过这套表达）

### 4.10 双相分离（旋钮 4：合并 → 物理规则）

- **一句话**：油永远在水上面，重的沉底——倒进去的顺序不重要，物理会重排。
- 容器：分液漏斗（栈，但**自动按密度排序**）；元素：带密度的液体
- 核心变化：容器内部会自动重排，玩家无法控制层序，只能控制「把什么倒进哪个容器」
- 胜利：每个漏斗只剩一种液体
- 难度旋钮：密度相近的液体对（会形成乳浊液，需要静置若干步才分层）、乳化剂元素（打乱密度）
- 独特钩子：**容器有自己的行为**，玩家从操作者变成条件设置者，是很少见的解谜视角
- 风险：自动重排会让玩家产生「不是我干的」失控感，必须把重排动画做得非常清楚

## 5. 优先级评估

打分为 1~5，「学习成本」越低越好（已反向计分）。

| 变体 | 学习成本↓ | 实现成本↓ | 机制差异化 | 留存/变现潜力 | 合计 |
|------|:---:|:---:|:---:|:---:|:---:|
| 4.9 归档室（容量泛化） | 5 | 5 | 3 | 3 | **16** |
| 4.1 分层特调（序列目标） | 4 | 4 | 4 | 4 | **16** |
| 4.4 调度场（图可达） | 3 | 3 | 5 | 4 | **15** |
| 4.3 书架归位（deque + 排序） | 3 | 3 | 5 | 3 | **14** |
| 4.8 听色（音高通道） | 4 | 3 | 4 | 2 | **13** |
| 4.5 显影（目标未知） | 3 | 3 | 5 | 2 | **13** |
| 4.6 反应釜（生成新元素） | 2 | 2 | 5 | 3 | **12** |
| 4.2 精确配液（数值） | 2 | 4 | 4 | 2 | **12** |
| 4.7 传送带（位置压力） | 3 | 3 | 3 | 3 | **12** |
| 4.10 双相分离（容器行为） | 2 | 2 | 5 | 2 | **11** |

**建议路线**：

1. **先做 4.9**：它是本作核心约束的直接泛化，逻辑层几乎不用改（容量表已经支持异构），可以作为「挑战模式」上线验证
2. **再做 4.1**：目标从单色变序列，是第一次真正动合并规则，但表现层直观、素材复用度高
3. **中期做 4.4**：图可达是差异化最强的一步，且**关卡内容 = 连接图**，能显著降低长期关卡产能成本
4. 4.6 / 4.10 留作实验分支：机制最新鲜，但可解性风险最高，必须先有强求解器

## 6. 可复用的技术底座

本仓库的三层结构（逻辑 / 求解 / 生成）已经与 UI 解耦，泛化到上面任一变体只需要抽出三个接口：

```ts
/** 一次可能的操作 */
interface Action { from: number; to: number }

/** 变体只需实现这四件事，求解器与关卡生成器即可复用 */
interface SortRules<S> {
  /** 列出合法操作（旋钮 1·5：容器形态与可达性） */
  actions(state: S): Action[];
  /** 执行操作（旋钮 4：合并 / 转化 / 重排） */
  apply(state: S, action: Action): S | null;
  /** 是否达成目标（旋钮 7） */
  isGoal(state: S): boolean;
  /** 规范化 key，用于搜索去重；必须把「不可互换的差异」写进 key */
  key(state: S): string;
}
```

本作的实现已经踩过两个坑，泛化时会再遇到：

1. **规范化 key 必须包含容器的固有属性**。容量不同的容器不可互换，只比内容会把不同局面误判为同一状态，剪掉真解。（本作 `boardKey` 把容量写进 key）
2. **防空转规则只在「两端完全等价」时才成立**。一旦容器异构，「满瓶单色不许再倒」这类规则会直接堵死正解——本作的做法是给这类规则加上「容量相同」的前置条件。

关卡生成一律走**「随机发牌 + 求解器正向校验」**，不要试图从通关态逆推：倒液不可逆，「从终局可达 S」不等于「从 S 可达终局」。这条对所有含不可逆操作的变体（尤其 4.6 反应釜）都成立。

## 7. 反模式清单

| 反模式 | 为什么错 |
|--------|---------|
| 只换素材（液体→彩球→螺丝） | 旋钮一个都没动，玩家 3 关内就会发现是同一个游戏 |
| 用未知色堆难度 | 未知色是**试探**成本不是**推理**难度，滥用后玩家只会无脑撤销。要配「同容器上限」这类约束 |
| 靠死局卖道具 | 死局应当是玩家决策失误的结果，而不是关卡生成的副产品。生成期必须校验可解 |
| 加倒计时 | 直接破坏「可随时中断」这条品类根基。压力要做成**步数刻度**这种可预测形式 |
| 目标不可读 | 「装满单色」之所以强，是因为一眼可判。任何新目标都必须能在容器上就地标注（配方缩略图 / 容量数字 / 索书号） |
| 不可逆 + 无求解器 | 会直接产出必败关卡，是这个品类最致命的 bug |

## 8. 与本作的衔接

短期（不改玩法，只补机制，均已有资料支撑）：

- **遮蔽容器**：某个瓶被罩住，凑齐指定整瓶颜色后才解锁（资料中的「遮蔽瓶子」）
- **单向阀瓶**：只进不出，进一步压缩腾挪空间（旋钮 5 的最小改动版）
- **挑战模式 = §4.9 归档室**：复用现有异构容量能力，容量改为质数分布
- **步数评级**：用求解器的最短解作基准给三星，让「解得漂亮」有反馈

长期：把 §6 的 `SortRules` 抽出来，让 4.1 / 4.4 作为独立关卡包接进同一个求解器与生成器，共用一套无障碍与存档基建。
